# Format package map — current implementation / proposed ownership

**No handlers or format packages have been migrated yet.** Every row currently routes through
FormatDetector/FormatRegistry metadata and MainViewModel's FileKind switch, not a dedicated handler.
The proposed package column is not a support claim. All families are unchanged and unverified in
this sandbox. `full`, `part`, `ident` below are the existing registry labels, not validated capabilities.

This inventory was derived from every literal registry entry at the preparation checkpoint. The
canonical generated capability matrix is still owned by `tools/GenFormatDocs.kt`; `docs/FILE_FORMATS.md`
was absent from the archive and has not been regenerated because Kotlin is unavailable. Preserve
that generator. Tests named below are existing regression entry points, not pass results.
